# Changing the design system

ejm-ui owns the design that `ejmlabs-design` summarizes for consumers. Load `ejmlabs-design` for
the shared rules (brand, layout, themes, motion, accessibility, copy). This skill says how to
change the owner so every consumer gets the change from one place.

## Before you start

- Read [the quality bar](../../../QUALITY.md), [the theme contract](../../../packages/ui/THEME.md)
  and [the component list](../../../packages/ui/COMPONENTS.md). If a name is not in THEME.md, it
  does not exist.
- THEME.md and the repository's AGENTS.md win over any older line in QUALITY.md. Its Depth section
  still says "Tone separates" cards and panels; there are no cards or panels.
- A pattern a consumer needs is added here as a token, component or recipe, then documented in
  the guide that owns it, in the same change. Consumers supply content and state only.

## Tokens and themes

- Change a color or theme value in `packages/tokens/theme.json` only. Run
  `npm run build -w @ejm/tokens` and commit what it writes under `packages/tokens/generated` and
  `packages/tokens/rust`. Never edit generated files.
- Copy the Rust palette into the crate with `node scripts/sync-rust-theme.mjs`. Never edit
  `crates/ejm-tui/src/theme.rs` by hand.
- A new color is a semantic role defined in both themes and on every band (paper, mist, sage,
  ink), added to the "What a band sets" table in THEME.md. Sage keeps Ink text and status; the
  chart hues stay undefined on Sage.
- The contrast gate is `node packages/tokens/scripts/contrast.mjs --verbose`, also run by
  `npm run check -w @ejm/tokens`. Never lower a pair's target. The only pairs below their usual
  level are the ones THEME.md names.
- Keep the Tailwind default palette, radius, shadow and font namespaces reset. That reset is what
  makes a stray color or shape fail to compile.
- After a token, recipe or font change, run `npm run build:static -w @ejm/ui` and commit
  `packages/ui/public/static.css`. The check rejects stale output.
- Fonts: rebuild subsets with `node packages/ui/scripts/build-fonts.mjs`. Keep the OFL notices
  in `packages/tokens/assets/fonts` and `packages/ui/src/fonts` identical.
- Art is generated by `node packages/ui/scripts/build-art.mjs` from the symbol outline. Never
  hand-edit files in `packages/ui/src/art`; `check-art.mjs` rejects stale output.
- Brand files live in `packages/tokens/assets` with a hash row in `assets/PROVENANCE.md`. See
  [the tokens guide](../../../packages/tokens/README.md) before adding or importing one.

## Components

- Pick the folder by the stylesheet profile that covers it: `components`, `layout`, `shell`,
  `hooks` and `motion` (default), `docs`, `app`, `static` or `terminal`. A default folder never
  imports from docs or app (`check-sources.mjs`).
- Choose the primitive in this order: a native element, then Radix when the behavior is hard to
  get right, then `@ejm/core` for a framework-neutral model. Record the choice and why in the
  COMPONENTS.md table; `check-components.mjs` fails on a component missing from it.
- Never name or class anything card, panel or tile (`check-components.mjs` and
  `check-containerless.mjs`). `ui-panel` is the window color and is allowed.
- Add the states it renders to the matching `packages/ui/src/catalog/*.json`, run
  `node packages/ui/scripts/build-catalog.mjs`, and add a contract component to
  `packages/core/contract.json`. `node scripts/parity.mjs --strict` compares the web, Ink and
  Rust catalogs with it.
- Show it in the gallery (`apps/gallery`): the API at `/docs/components`, examples in both themes
  at `/components`.
- Export it as `ejm-ui-packages` says. Anything outside `exports` is private.

## Recipes

- Site composition recipes are `Page`, `Hero`, `SectionHead` and
  `packages/ui/src/layout/SiteContent.tsx`. Sites cannot change a recipe with classes, so change
  the recipe here and update [the layout guide](../../../packages/ui/src/layout/README.md).
- Control recipes (`buttonVariants`, `fieldClass`) live in `packages/ui/src/control-recipes.mjs`
  and feed both the React wrappers and the static build. Change them there only.
- Native HTML recipes are the `data-ejm` attributes in `static.css`, documented in
  [Native HTML applications](../../../packages/site/native-html.md). Update that guide with them.

## Terminal blocks

- Rust blocks live in `crates/ejm-tui/src`, their Ink twins in `packages/ink`. Both follow
  `packages/core/contract.json` and the shared cases in `packages/core/terminal-fixtures.json`.
  Change the contract, the crate and Ink together; the crate tests fail until all agree.
- `cargo test` rewrites `crates/ejm-tui/catalog.json`; `npm run catalog -w @ejm/ink` rewrites the
  Ink catalog. Commit both. Rust rules are in `ejmlabs-rust`. Read
  [the crate guide](../../../crates/ejm-tui/README.md) before adding a block.

## Gates for a visible change

- `npm run check` covers contrast, stale generated files, components, sources, tree shaking,
  catalogs, parity, types and tests. Then build, shoot and measure as `ejm-ui-testing` says.
- Walk every QUALITY.md dimension on the gallery route that shows the change, in light and dark.
  Follow `ejmlabs-design` and its review reference for screenshots and keyboard checks.

## How consumers pick up a change

- Consumers pin ejm-ui by a full commit SHA and link its packages (`file:` or tarballs, see
  [the adoption guide](../../../ADOPTION.md)). Nothing reaches a consumer until its pin moves.
- After the change merges here, each consumer moves its pin to the merge commit in its own
  repository and PR, reinstalls, runs its own checks and load-time baseline, and deploys from
  there. Adopt and verify each consumer in its own repository.
- Before renaming or removing a public name (export path, token, prop, recipe, `data-ejm`
  attribute), search the consumer repositories for it. List the follow-up pin moves in the PR and
  add upgrade notes under the unreleased section of `CHANGELOG.md`.
