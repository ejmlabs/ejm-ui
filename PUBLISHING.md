# Publishing

How the npm packages in this repository are published. Source releases follow [Releases](RELEASING.md).

`@ejm/tokens`, `@ejm/core`, `@ejm/ui` and `@ejm/ssg` publish together at the version in `VERSION`; every other workspace package stays private. The **Publish npm packages** workflow is run from `main` by a maintainer after the draft release is reviewed. It is disabled until the repository variable `NPM_SCOPE_CONFIRMED` is `true`, which the owner sets once the `@ejm` npm scope is owned and trusted publishing is configured for each package. Its build job checks, packs and proves the four tarballs with read-only access and no secrets; a separate job publishes those exact tarballs with provenance and runs no project code. Run `node scripts/pack-proof-publish.mjs` before changing a manifest, `files` or `exports` of the four packages. The tokens tarball must not carry reserved brand artwork. Owner setup: restrict the `npm-publish` environment to `main` as well as a required reviewer, and name that environment and `publish.yml` in each package's npm trusted publisher. If a publish stops partway, versions already published cannot be republished: fix it with a new version. A published version cannot be replaced.
